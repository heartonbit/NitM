# 운영 및 장애 대응

## 정상 동작 확인

- `/api/health`: Worker HTTP 경로
- Google OAuth callback 상태 및 로그인 결과
- Workers & Pages 로그: Cron 실행, RSS 소스 실패, LLM 상태 코드, Resend 상태
- D1 `runs`: 날짜별 결과와 사용자/수집/발송 집계
- D1 `deliveries`: 사용자별 상태, 오류 코드, 수신자 스냅샷, 메일 본문
- 관리자 화면: 최근 실행·생성 브리핑·수신자 포함 전송 이력

뉴스 이메일 footer의 **요청 모델**은 `LLM_MODEL` secret 값이며, **응답 모델**은 LLM API 응답의 `model` 필드에서 수집한 값이다. 응답에 `model` 필드가 없으면 미기록으로 표시한다. migration 0005 이전 lesson은 응답 모델을 저장하지 않았으므로 이전 캐시를 재사용해 보낸 메일에는 기록 없음으로 나올 수 있다.

## 뉴스 요약 기준

매 실행 시 활성 RSS/Atom 미디어에서 실행 시각 직전 24시간 동안 게시된 피드 항목을 모두 모은다. 게시 시각이 없거나 유효하지 않은 항목은 시간 범위를 증명할 수 없어 제외한다. LLM 분류는 제목에서 한국 단서를 정확히 인용하고 기사의 주제가 직접 한국 관련일 때만 통과한다. 요약문에 한국이 배경·비교로만 등장하거나 인용 근거가 제목에 없으면 본문을 수집하지 않는다. 통과한 기사 URL만 재검증 후 본문 HTML을 가져오며, 응답은 2MB, 추출 본문은 기사당 6,000자로 제한한다. 본문 수집이 안 되면 RSS 제목·요약으로 계속 처리한다. 다른 기사는 피드 제목·요약을 사용하며 전체 원문 페이지를 일괄 크롤링하지 않는다. 모든 항목은 크기 제한 묶음으로 처리하며 소스당 3건 제한은 없다. 요약의 기사/토픽 제목과 이메일 출처 링크는 `{출처} {제목} [[published:원본 날짜·시각·timezone]]` 구조를 사용한다. 이메일에는 Politico, FT, Euractiv를 P, F, E 색상 배지로 표시하며, 게시 일시는 원래 시간대를 유지해 `yy/mm/dd hh:mm`으로 표시한다. 병합된 기사에는 실제 시각이 가장 빠른 일시 하나를 표시한다. 연도가 없는 과거 캐시의 일시는 추정하지 않고 기존 표기를 유지한다. 요약은 한국어이며 한국 관련 소식은 상단에 배치한다.

## 수동 테스트

관리자 화면의 **테스트 메일**은 활성 RSS 소스를 수집하고 LLM 요약을 생성해 관리자 본인에게 전송한다. 테스트는 정규 일일 전달 이력이나 날짜 잠금을 생성하지 않는다. **지금 발송**은 활성 구독자를 대상으로 오늘 날짜의 실제 브리핑을 저장하고 전달 이력에 기록한다.

## 안전한 오류 코드

| 코드 | 의미 | 확인할 항목 |
|---|---|---|
| `no_subscribers` | 수신 사용자가 없음 | 사용자 구독 상태 |
| `no_news` | 수집 가능한 기사 없음 | 활성 소스 URL/응답/피드 구조 |
| `llm_not_configured` | LLM key, Base URL 또는 model secret 누락 | `LLM_API_KEY`, `LLM_BASE_URL`, `LLM_MODEL` secret 등록 상태 |
| `lesson_generation_error` | LLM 오류 또는 비정상 응답 | 공급자 상태·모델 접근·요청 제한 |
| `email_error` | Resend 전송 실패 | 키, 발신 도메인, 수신 제한/계정 |
| `digest_error` | 기타 파이프라인 오류 | Worker 상세 로그와 D1 실행 기록 |

상세 provider 응답은 개인정보나 비밀값 노출을 피하기 위해 DB의 오류 코드에는 복사하지 않는다.

## 재시도 및 멱등성

- 날짜 잠금이 `sent`면 Cron 재호출은 건너뛴다. 실패한 잠금은 다음 예약 또는 수동 실행에서 다시 시작할 수 있다.
- 발송 성공은 `UNIQUE(date,user_id)` 전달 레코드로 기록한다. 같은 날짜의 재실행은 성공 사용자를 건너뛰고 실패 사용자만 재시도한다.
- Resend가 성공한 후 D1 쓰기가 실패하는 매우 좁은 구간에는 중복 발송 가능성이 있다. provider idempotency 지원을 도입하기 전에는 운영자 로그로 해당 상황을 확인한다.
- 일일 실행이 너무 오래 걸리면 Cloudflare Worker CPU/시간 한도와 Resend 제한을 확인하고 사용자 수를 줄이거나 큐 기반 분할을 별도 설계한다.

## 보안 사고 대응

비밀 노출이 의심되면 Cloudflare에서 해당 Worker secret을 즉시 교체하고 Worker를 재배포한다. Google OAuth client secret이 노출되면 Google Cloud Console에서 교체하고 새 값을 Worker secret에 등록한다. 초대 삭제는 앱 권한을 제거하지만 기존 사용자 문서 자체를 삭제하지 않는다. 현재 관리자 제거 UI는 없으므로 잘못 지정된 부트스트랩 주소는 배포 설정을 수정하고 D1 `admins`를 통제된 운영 절차로 수정한다.

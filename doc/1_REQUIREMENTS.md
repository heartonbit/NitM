# 요구사항 및 범위

## 목적

등록된 사용자를 대상으로 관리자가 관리하는 뉴스 미디어의 최근 뉴스를 수집하고, LLM으로 일일 브리핑을 작성해 설정된 시간에 이메일로 전송한다. 생성물, 전송 내용과 처리 이력을 날짜별로 조회할 수 있어야 한다.

## 기능 요구사항

| ID | 요구사항 | 구현 기준 |
|---|---|---|
| R-01 | Google 로그인 | Worker가 Google OAuth Authorization Code flow를 수행하고 검증된 이메일만 수락 |
| R-02 | 사용자 초대 | 관리자가 이메일을 초대 목록에 등록하고 초대 링크 이메일을 보낸다. 초대된 주소로 로그인해야 사용자 문서가 만들어진다. |
| R-03 | 사용자 관리 | 관리자는 등록 여부와 구독 상태를 확인하고 수신을 중지/재개할 수 있다. 사용자는 본인의 메일 수신을 중지/재개할 수 있다. |
| R-04 | 뉴스 미디어 관리 | 관리자만 RSS/Atom URL, 이름, 정렬 및 활성 상태를 관리한다. |
| R-05 | 일일 요약 | 활성 RSS/Atom 소스에서 최근 24시간 내 게시된 모든 피드 항목을 수집하고, 누락 없이 한국어로 번역·요약한다. 한국 관련 기사는 브리핑 상단에 먼저 배치한다. |
| R-05a | 뉴스 출처 | 요약 이메일 끝에 수집된 각 기사의 실제 제목, 원문 URL, 미디어명을 링크 목록으로 표시한다. |
| R-06 | 예약 발송 | 관리자가 IANA 시간대와 현지 발송 시각을 설정한다. Worker Cron은 매분 확인하며 날짜별 잠금으로 중복 실행을 제한한다. |
| R-07 | 메일 테스트 | 관리자는 실제 수집·요약·Resend 전 과정을 본인 주소로 시험한다. |
| R-08 | 수동 발송 | 관리자는 현재 구독자를 대상으로 당일 브리핑을 즉시 실행한다. 이미 성공 발송한 사용자에게 중복 전송하지 않는다. |
| R-09 | 날짜별 열람 | 관리자는 날짜별 생성 브리핑 원문을, 사용자는 본인에게 발송된 메일 본문을 조회한다. |
| R-10 | 발송 이력 | 관리자는 최근 수신자·제목·상태·메일 본문을 확인한다. 사용자는 본인 최근 100건을 조회한다. |
| R-11 | 보관 만료 | 30일보다 오래된 브리핑·이력·실행·감사 기록을 일일 작업에서 삭제한다. |
| R-12 | 장애 진단 | 안전한 오류 코드와 실행 집계는 D1에 저장하고, 상세 예외는 이메일·API 키 등 개인정보를 제외해 Worker 로그에 남긴다. |

## 비기능 요구사항

- 실행 구성은 Cloudflare로 한정한다. D1은 서비스 DB, Worker는 API/OAuth/Cron, Workers Assets는 UI를 제공한다.
- 사용자는 본인의 설정과 전송 내용만 조회한다. 관리자 변경과 외부 발송은 서버에서 권한을 검사한다.
- LLM 입력은 기사 항목 단위로 나눠 처리하며, 크기 제한 때문에 기사를 잘라내거나 누락하지 않는다.
- HTML 메일에는 LLM·기사의 원시 HTML을 삽입하지 않는다.
- 모든 비밀은 Cloudflare Worker secret으로 저장하며 브라우저 자산 및 DB에 기록하지 않는다.

## 범위와 초기값

- 초기 뉴스 미디어는 BBC, The Guardian, CNN, AP, Le Monde, The Brussels Times이며 관리자 화면에서 바꿀 수 있다.
- 초기 요약 언어는 Korean, 시간대는 UTC, 발송 시각은 06:00이다.
- 수신 주소는 Google 로그인 이메일이다. 별도 주소 변경, 언어별 구독, 읽음 streak, 웹 달력은 이번 RFP 범위에 포함되지 않는다.
- 비밀번호 로그인, 결제, 사용자별 발송 시각, 기사 원문 저장은 범위 밖이다.
